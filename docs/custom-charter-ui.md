# Standalone charter dashboard (0.0.9)

Frontier's custom menu is independent. It does not bundle MineScape UI, textures,
behavior scripts or identifiers, and it does not require MineScape to be enabled.
The supplied MineScape pack was a technical reference; its copied menu definitions
and assets from 0.0.4 have been removed.

## Separate controls and assets

- `ui/jagsby_frontier/charter.json` defines Frontier's own `jagsby_frontier`
  namespace, dashboard, router, sidebar toggles, page panels and action controls.
- `ui/_ui_defs.json` registers that definition file with the Minecraft UI loader.
- Frontier's pixel-art frame, sidebar icons and states are generated by
  `tools/build_ui_art.py`. The design follows the user's Village Charter concept.
- Fixed transport records supply live settlement text and action indices. The
  Script API form is the transport; the custom JSON UI draws the charter menu.
- Four local sidebar tabs switch panels without submitting the form, reopening
  the menu or recalculating the census. The biome picker has its own custom view.

## Minimal vanilla entry hook

Bedrock creates Script API forms through the vanilla `server_form_factory`.
`ui/server_form.json` contains only the small hook routing long forms into
Frontier's router. Titles beginning `JF_CHARTER|` use Frontier's custom controls;
all other titles render through `server_form.long_form`, Minecraft's original
renderer. A separate modal router sends only `JF_CHARTER|Rename` to Frontier's themed
rename view, which uses Minecraft's text-input control and a custom Save button.
Other modal forms use the vanilla renderer.

The hook is necessary for this Bedrock JSON UI mechanism; it is not a MineScape
component or dependency. Other packs modifying the same vanilla entry point can
still conflict, but Frontier requires no other addon and no specific ordering
relative to an absent MineScape pack.

## Development and verification

`python tools/addon.py build` regenerates the artwork, separate JSON UI, matching
script layout and vanilla villager bridge before validating and packaging.

Tests check standalone registration, default-form routing, local tabs, matching
record indices and resolution of Frontier's own control/texture references. They
do not render the Minecraft client. In a world using only Frontier, check opening,
all four tabs, research, biome selection, collection and closing on the intended
input devices. The stable API target remains Bedrock 1.26.0+, server 2.9.0 and
server-ui 2.1.0.

## Compact Overview

The Overview is a fixed 257×177 panel with three fields: settlement name, village biome, and Realm Power. Rename is in the crimson
header, outside the settlement details. It has no scroll container or
extra research, population, coordinate or stockpile details. Long names are
bounded to 24 characters for new renames and clipped within the name region.
Renaming saves to persistent settlement state and returns to the same Overview;
it does not rerun the villager census. A ≥ prefix on power indicates a minimum
estimate if trade rank data could not be obtained.

## Research subtabs and binding correction

Research has Global and Local radio-toggle subtabs in a separate toggle group
from the main sidebar. They select separate upgrade lists without submitting a
form or scanning villagers again. After a purchase or failed affordability check,
the menu returns to the corresponding research group.

The index-only approach used in 0.0.7 did not resolve the user's in-game
binding failure. In 0.0.8, labels and actions are generated by native record
factories instead. Each factory receives the native collection context. Data
records carry `[JF:data:key]` tags; the label only shows its matching record and
removes that tag from the displayed text. Action controls filter matching
`[JF:action:key]` tags and return the native selection index. This avoids the
unreliable manually assigned `collection_index` path.

The approved 64×64 transparent sprite assets are displayed in all four visual
states of Overview, Research and Production. The generated button backgrounds
no longer bake the old placeholder drawings underneath them. Research subtabs
remain text-only.

## Tier portrait Overview

The Overview's 257×177 area now contains a 96×168 tier portrait at the left,
a 96×9 tier caption below it, and the three detail fields in the right column
beginning at x=108. All regions fit within the fixed area. The tagged tier record
includes its image texture so the native image factory can display Outpost,
Hamlet, Village, Town or City from the latest saved census. See
`settlement-portrait-assets.md` for the agreed provisional thresholds.
